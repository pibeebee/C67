# C67 Foundation Lab — implementation and evaluation

4 November 2026, Asia/Jakarta. App 0.1, final build 3; model prompts `foundation-lab-v3`.

The separate iPhone app and shared macOS runner are implemented. Import, explicit preferences, model suggestions, MapKit candidate retrieval, deterministic fallbacks, local history, and JSON/Markdown export are available. **This is a research PoC: reliable autonomous recommendations and reduced user effort are not established.**

## Final English model evaluation

24 synthetic cases × three fresh processes/sessions = 72 final attempts. Each capability has six distinct cases and 18 attempts. The two earlier 72-attempt series are preserved as developmental evidence, so 216 attempts are retained across all three versions. V2 addressed candidate-list padding/duplicates; V3 compacted the candidate prompt after the phone's smaller context window was observed. This final set was already seen during development and is **not a blind holdout**.

| Capability | Attempts | Shape/references valid | Selected objective checks clear | Response-only p90 |
| --- | ---: | ---: | ---: | ---: |
| preferences | 18 | 18 | 15 | 1.45 s |
| candidates | 18 | 15 | 6 | 3.19 s |
| windows | 18 | 15 | 15 | 3.82 s |
| explanation | 18 | 15 | 15 | 3.63 s |

These counts are not full semantic accuracy or production acceptance. Every response still has two independent human-review slots pending in `human-review.csv`. Greedy repetitions are correlated. The measurements mix service warm/cold states and may include background work; Mac p90 is not an iPhone target result. Final attempts had no timeout; all rejected responses remain in raw artifacts.

Representative failures:

- P05 added outdoor/photography interests that were not requested and returned balanced instead of packed pace. Valid shape did not establish correct intent.
- Candidate selection remained weak: some outputs included an unrelated gallery while their note said only the cafe matched; duplicate choices were also observed. Correct evidence IDs alone did not prove relevance.
- W03 proposed afternoon despite the supplied closing time of 10:00. Native validation rejected the conflicting window.
- E05 introduced an evidence ID absent from the input. Native validation rejected it. This case does not establish general prompt-injection resistance.

The most useful next investigation is improving candidate relevance and intent fidelity, then obtaining independent reviews and fresh paraphrases. A passing field check cannot establish useful onboarding or sound venue advice.

## Provider and device observations

The final Mac live pipeline took **14.70 seconds**, with 10 MapKit candidates. Preferences, visit windows and explanation passed shape/reference checks; candidate output was rejected and a clearly labelled deterministic shortlist was used. The same-input deterministic run took **0.89 seconds**. This is one observational comparison, not a latency benchmark or user study. The deterministic path uses explicit choices and does not interpret the English sentence; effective pace can therefore differ. Search was performed twice, so provider observations are not assumed identical.

The iPhone smoke run took **16.36 seconds** and returned 10 MapKit candidates with no search errors. Its runtime reported English supported, Indonesian unsupported, and a **4,096-token context**; the Mac reported 8,192. The compact candidate request used 1652 measured input/schema/instruction tokens, preserving all 10 candidates and their evidence. Preference, candidate and explanation outputs passed shape/reference checks. Visit-window output cited place ID `A` as an evidence ID; validation rejected it and retained the template.

The ordinary iPhone run before compacting inputs is retained separately. Its candidate stage was blocked by the context-budget check, and a model response to empty free text also added a reading interest. The delivered empty-input guard removes that inference path; it does not claim to repair arbitrary model misunderstandings.

Device evidence is from the actual iPhone application, not the Mac runner or Simulator. It used imported or synthetic itinerary data; no journey, GPS attendance, traffic accuracy or full physical-device interaction walkthrough was established. Earlier launch attempts were blocked by the lock screen or did not yield a console completion marker; those failures are retained. A direct-argument launch produced the completed smoke JSON. The user unlocked the phone for testing. Final build 3 adds the native empty-input guard; the scripted phone run used build 2 with the same nonempty-text model pipeline.

Inference explicitly selects the Apple system model. No hosted AI fallback is configured. There was no packet-capture audit or independent daemon network isolation. MapKit used network-backed search. No routing/weather/search offline claim is made.

## Product boundary and handoff

- Only Jakarta, WIB, one day, at most six stops. The original service date and schedule are preserved.
- New places and broad time windows remain proposals. Detour, new ETA, visit order, finish time and full schedule feasibility have not been recomputed.
- Price, quietness, accessibility, crowd levels and unsupported opening/weather details stay unknown. MapKit category alone cannot verify them.
- The app preserves explicit profile choices separately from trip text. It records session submission/correction rounds, not measured reductions in user effort.
- Imported facts and every model output are available in the experiment view. Templates and fixture outputs are labelled; they are never reported as successful model inference.
- Human semantic reviews, fresh unseen inputs, wider iPhone repetitions, full physical UI validation and participant comparisons remain outstanding. None is silently marked passed.

The work writes only under `poc/c67-foundation-lab`. All 25 monitored Swift files in the older routing PoC matched their starting hashes. Its project.pbxproj changed during concurrent work; the before/after observation is recorded, with attribution left separate. This task did not write or restore files in that checkout. No Git commit, push or production deployment was performed.
