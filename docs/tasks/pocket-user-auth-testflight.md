# Pocket user authentication for TestFlight

Status: authenticated Pocket server deployed on 16 November 2026; real Apple account and TestFlight validation pending.

Pocket's `pocket-auth` app mode signs in with Apple via Supabase Auth, obtains a refreshable user session and sends the current access token to the preconfigured Pocket HTTPS endpoint. Saved trips are isolated by account ID on the device. The previous shared trip file remains untouched and is not silently imported into an account. Signing out returns to the Apple login screen.

The Pocket server's opt-in `authenticated` mode validates access tokens at Supabase Auth `/auth/v1/user`; job records are scoped to the verified account. SQLite migration adds an owner to legacy jobs without deleting them. Legacy jobs are not visible through authenticated sessions. Existing `legacy` mode remains the default until a reviewed deployment. A failed auth service returns an unavailable response rather than silently accepting a shared token.

## Verification and blockers

- Local tests: 45 synthetic Pocket server tests, 70 C67Backend tests, and the simulator Apple sign-in gate passed. The Release app compiled for generic iOS without signing, and its plist contained `pocket-auth`, the Pocket URL and a publishable client key; no shared Pocket token or provider secret was embedded.
- On 16 November 2026, the old `supabase.mrt.qzz.io` hostname did not resolve. The owner supplied `supabase.giovanc.com`; its Auth health endpoint returned HTTP 200 with the publishable key, and the Pocket container reached it over HTTPS. `API_EXTERNAL_URL` already uses the new host. The Pocket `/health` endpoint returned HTTP 200. The existing Supabase Auth container reports Apple sign-in enabled, nonce checking enabled and the C67 bundle ID configured; no real login was attempted.
- The active Pocket container did not have the four WeatherKit REST variables configured; after deployment it will use Open-Meteo until valid server-side WeatherKit credentials are separately configured and tested.
- The ignored Release override holds the verified publishable/anon client key and new Auth hostname, and now enables `pocket-auth`. Simulator fixtures and an unsigned Release build do not establish TestFlight readiness.
- On 16 November 2026, a signed Release archive was uploaded to App Store Connect as version 0.1.0 build 2. Apple initially rejected an icon with transparency; the opaque icon passed upload. Export compliance was completed and the build reached Ready to Submit; external distribution has not been confirmed. Physical-device Apple login, token refresh and revocation, two-account job isolation and weather-provider checks still require verification. Do not assign the legacy local trip file to an account without an explicit migration choice.
